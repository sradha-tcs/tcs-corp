## Site and locale hierarchy

**Purpose.** One Edge Delivery site serves 13 locale sites by path. Each locale owns its pages and its own references, error pages, sheets, data and block library.

**Structure.** The AEM tree `/content/tcs-corp/{country}/{language}` is published at a language-only path. The locales are defined once in `LOCALES` ([`utils/site.js`](../../../utils/site.js)); the first entry is the default (`DEFAULT_LOCALE`, `en`).

| AEM folder | Published root | `lang` | | AEM folder | Published root | `lang` |
| --- | --- | --- | --- | --- | --- | --- |
| `us/en` | `/en` | en-US | | `se/sv-se` | `/sv-se` | sv-SE |
| `de/de-de` | `/de-de` | de-DE | | `dk/da-dk` | `/da-dk` | da-DK |
| `fr/fr-fr` | `/fr-fr` | fr-FR | | `no/no-no` | `/no-no` | no-NO |
| `ca/fr-ca` | `/fr-ca` | fr-CA | | `cn/zh-cn` | `/zh-cn` | zh-CN |
| `es/es-es` | `/es-es` | es-ES | | `jp/ja-jp` | `/ja-jp` | ja-JP |
| `pt/pt-pt` | `/pt-pt` | pt-PT | | `kr/ko-kr` | `/ko-kr` | ko-KR |
| `nl/nl-nl` | `/nl-nl` | nl-NL | | | | |

```text
/content/tcs-corp/
├── {country}/{language}/   a locale site; the locale page itself is Home (published as /{locale}/)
│   ├── …                   content pages
│   ├── references/         nav, footer, alternative navs / footers, footer Canvas page, modals, fragments
│   ├── error-pages/        404 (used by 404.html); 403 / 500 for a CDN
│   ├── block-library/      block validation pages; excluded from publishing
│   ├── placeholders        sheet: Key, Text, Description, Category
│   ├── metadata            sheet: bulk metadata
│   ├── taxonomy            taxonomy page (tag, title)
│   ├── redirects           sheet: Source, Destination
│   └── data/               sheets: authors, locations, partners, social-links, media-contacts
├── language-master/en/     temporary: published at /language-master/en for review
└── site-global-templates/  template pages authors copy; excluded from publishing
```

**Path mapping (`paths.json`, generated by `npm run build:paths` from `LOCALES`).** Per locale: the folder mapping (`/content/tcs-corp/de/de-de/:/de-de/`), the Home page mapping (`/content/tcs-corp/de/de-de:/de-de/`), 8 sheet mappings (`placeholders`, `metadata`, `redirects`, `data/authors`, `data/locations`, `data/partners`, `data/social-links`, `data/media-contacts`; spreadsheets get `.json` appended) and the taxonomy page (`…/taxonomy:/de-de/taxonomy.json`): 143 mappings. Temporarily 11 more for the language master. `includes`: the 13 locale pages, `/content/dam/tcs-corp/` and `/content/tcs-corp/language-master/en`; `excludes`: each locale's `block-library` and `block-library/**`, and `site-global-templates` with its children. AEM applies the site configuration's `public.json` → `paths`, not the repository file (AGENTS.md "Notes").

**Locale resolution (code).** `getLocale(pathname)` reads the AEM path when editing (`/content/tcs-corp/de/de-de/…`) and the published path on the site (`/de-de/…`); pages outside a locale (Site Global Templates, drafts) get `en`. Helpers: `localePagePath`, `resolvePagePath`, `localeSheetPath`, `toPublishedPath`, `toAemPath`, `pageLink`, `getParentPages`, `sheetRows`.

**Language master under review (temporary).** Pages below `/language-master/en` (`REVIEW_ROOTS`) list their own pages from the query index (`indexRoot`), read their own placeholders, redirects, taxonomy and data sheets (`REVIEW_SHEETS`), use their own `references/` and `error-pages/` (`REVIEW_PAGES`) and inherit up to `/language-master/en`. Remove after the rollout (handover Part 3.9, finding F-88).

**Rules.**

- Add or change a locale only in `LOCALES`, then run `npm run build:paths` and commit both files; the site administrator re-applies `public.json` and `metadata.source`.
- Nothing is published at `/`: a `/` → `/en/` redirect needs another mechanism (handover F-36).

**Common mistakes.** Editing `paths.json` by hand (it is overwritten by the generator); expecting a repository `paths.json` change to take effect without the site configuration; creating pages directly under `/content/tcs-corp` (not published).

## Page structure

**Purpose.** A page is a sequence of sections; each section holds default content (text, headings, images, links) and blocks. The structure is the contract between author and code (AGENTS.md "Blocks").

**Page properties** (`models/_page.json`, model `page-metadata`):

| Field | Name | Effect |
| --- | --- | --- |
| Title | `jcr:title` | `<title>`, `og:title` |
| Description | `jcr:description` | `description` meta |
| Keywords | `keywords` | `keywords` meta |
| Page Type | `page-type` | Default (empty), Home `home`, Article `article`, Blog `blog`, Press Release `press-release`: body class and template |
| Navigation | `nav` | Header page, inherited by child pages |
| Footer | `footer` | Footer page, inherited by child pages |
| 404 Page | `error-page` | 404 page of the subtree, inherited |

Page tags are not a field of this model; they come from the standard AEM page properties (`cq:tags`, published as `cq-tags`) or a `tags` column of the bulk metadata sheet (handover Part 7.1.1).

**Section properties** (`models/_section.json`), applied by `decorateSectionsWithOptions` in `scripts/scripts.js`:

| Field | Name | Delivered as | Result |
| --- | --- | --- | --- |
| Section Name | `name` | — | Not one of the section options read by `scripts.js` |
| Style | `style` | section classes | Default, Grey `bg-grey`, Dark `bg-dark`, Dark Green `bg-dark-green` (colour only; dark ones apply the theme contract in `styles/styles.css`) |
| Width Type | `sectionWidth` | `data-sectionwidth` | `fixed-width` class (full width is the default) |
| Rounded edge | `roundedEdge` | `data-roundededge` | `rounded` class |
| Background Image / Image alt text | `backgroundImage`, `backgroundImageAlt` | data attributes | `.section-background` with a responsive picture, `has-background` |
| Anchor name | `anchorName` | `data-anchorname` | section `id` (suffixed `-2`, `-3` when taken) |

Documents that use a `section-metadata` block are read the same way (rows `Section Width`, `Rounded Edge`, `Background Image`, `Background Image Alt`, `Anchor Name`).

**Container sections.** Gen Carousel, Tabs Container and Columns Container are sections whose content `scripts.js` wraps in a synthetic block (`gen-carousel`, `tabs`, `columns-container`). Sections don't get `classes_*` fields delivered, so their Additional tab fields are `container*` data attributes turned into block classes by `applySectionBlockOptions` (AGENTS.md "AEM delivery rules"; [columns-container](../../../blocks/columns-container/README.md), [tabs](../../../blocks/tabs/README.md), [gen-carousel](../../../blocks/gen-carousel/README.md)).

**Blocks and default content.** The `section` filter allows 26 components (`component-filters.json`); the inventory and each block's content contract are in [blocks/README.md](../../../blocks/README.md). Repeating content is item children added with Add, not composite multifields (AGENTS.md "Item children").

**Common mistakes.** Putting a section inside a Tabs Container (a section can't hold a section: use Column Breaks); relying on a section `classes_*` field (not delivered); adding sample text to templates or model defaults (stored on every new component).

## Templates

**Purpose.** A Page Type gives recurring page kinds their structure. Template pages that authors copy live in `/content/tcs-corp/site-global-templates/` (not published).

**Structure.** `loadTemplate` (`scripts/scripts.js`) loads `templates/{name}/{name}.js` and `.css` when the Page Type (`page-type`, else `template` metadata) is in `TEMPLATES`:

| Page Type | Adds | Data |
| --- | --- | --- |
| `home` | Layout styles only | — |
| `article` | A Page Header from the page metadata (unless authored), "About the author" | Authors sheet (`author-id`) |
| `blog` | The article structure and styles | Authors sheet |
| `press-release` | A Page Header (unless authored), "Media contacts" | Media Contacts sheet, filtered by the page's `region`, else all |

Source: [templates/README.md](../../../templates/README.md) (including how to add a template).

**Rules.** The Page Type page property wins over the metadata sheet's `page-type` column; Page Type also becomes a body class. Changing a template page doesn't change pages already copied from it (handover Part 4.8).

**Common mistakes.** A `page-type` value that isn't in `TEMPLATES` (only the body class is added); expecting template content in the query index (templates build DOM in the browser).

## Metadata model

**Purpose.** Page-level values (SEO, social, card content, page type, author, dates, flags) that code, the query index and the data layer read. Every value is a `<meta>` in the server-delivered head.

**Sources and precedence.**

| Source | Where authored | Published as |
| --- | --- | --- |
| Page properties (`models/_page.json`) | Universal Editor page properties | `<title>`, `description`, `keywords`, `page-type`, `nav`, `footer`, `error-page` metas |
| Standard AEM page properties | Sites console (e.g. Tags `cq:tags`) | `cq-tags` (one comma-separated meta) |
| Bulk metadata sheet | `/content/tcs-corp/{country}/{language}/metadata` | `/{locale}/metadata.json`; each column becomes `<meta name="{column}">` on pages matching the row's `url` pattern |

Page-level values win over bulk metadata; bulk rows apply top to bottom (handover Part 8.1.2). The bulk sheets apply only once all 13 are listed in the site configuration's `metadata.source`, and each sheet's URL patterns must start with its locale (`/de-de/**`) (AGENTS.md "Notes").

**Bulk metadata columns** (AGENTS.md, 41 columns): `url`, `page-type`, `meta-title`, `meta-description`, `meta-keywords`, `author-id`, `publish-date`, `modified-date`, `reading-time`, `og-title`, `og-description`, `og-image`, `og-type`, `twitter-card`, `twitter-title`, `twitter-description`, `twitter-image`, `canonical-url`, `robots`, `region`, `country`, `language`, `persona`, `thumbnail-image`, `featured-image`, `campaign-id`, `content-type`, `featured`, `priority`, `listen-link`, `author`, `card-title`, `card-description`, `card-image`, `card-image-alt`, `image-alt`, `eyebrow`, `category`, `hide-in-nav`, `card-style`, `card-theme`.

**Consumers.**

| Consumer | Reads | Source |
| --- | --- | --- |
| SEO decorator (eager) | `meta-title` → `<title>`; `meta-description`, `meta-keywords`; `og-*` (falling back to `meta-*`); `twitter-*` (falling back to `og-*`, `meta-*`); `canonical-url` → `<link rel="canonical">` and `og:url`; `language` → `<html lang>` | [`decorators/seo-decorator.js`](../../../decorators/seo-decorator.js) |
| `getPageMetadata()` | title, description, image (`featured-image`, else `og:image`), `page-type` (else `template`), `content-type`, `category`, tags, `author-id`, `author`, `publish-date` (else `publication-date`), `modified-date`, `reading-time`, `listen-link`, `thumbnail-image`, `featured-image`, `image-alt`, `region`, `country` (else the locale's), language, `persona`, `campaign-id`, `featured` (yes / true / 1 / on / y), `priority` (number) | [`utils/metadata.js`](../../../utils/metadata.js) |
| `getPageTags()` | `article:tag` metas and `cq-tags`, else a comma-separated `tags` meta | `utils/metadata.js` |
| `getPageLanguage()` | `language` when it is a language code, else the locale's `lang` | `utils/metadata.js` |
| Page Header, templates, data layer page entry | `getPageMetadata()` | [page-header](../../../blocks/page-header/README.md), `decorators/data-layer-decorator.js` |
| Query index | the server head (see [indexing-and-search.md](./indexing-and-search.md)) | `helix-query.yaml` |

**Rules.** The query index reads the server-delivered head, so values set by JavaScript (the SEO decorator's) aren't indexed (handover Part 8.1.3). `robots` is a standard name and works server side. Use `card-*`, `eyebrow`, `hide-in-nav`, `card-style`, `card-theme` for List cards (List README "Page metadata contract").

**Example.**

```text
url                   | page-type      | hide-in-nav
/de-de/newsroom/**    | press-release  |
/de-de/insights/**    | article        |
/de-de/legal/imprint  |                | yes
```

**Common mistakes.** A sheet row pattern without the locale prefix; adding columns to a sheet that isn't listed in `metadata.source` (no effect); expecting a metadata change to reach lists before the page is republished and indexed. Field reference per column: handover Part 8 — Metadata Documentation (8.2, 8.4).

## Taxonomy

**Purpose.** Tag IDs on pages and in block fields are turned into localised labels at runtime.

**Structure.** Tags are maintained in AEM Tagging; a taxonomy page per locale (`/content/tcs-corp/{country}/{language}/taxonomy`) is published as `/{locale}/taxonomy.json` with columns `tag` and `title`. With translated titles the JSON is multi-sheet: `loadTaxonomy()` reads the sheet named after the locale's ISO 639-1 language (`de`), else `default`, else the first sheet (`sheetRows`).

**Consumers.** `resolveTags(values)` ([`utils/taxonomy.js`](../../../utils/taxonomy.js)): a value with a taxonomy entry gets its title; a value containing `:` or `/` without an entry gets a label derived from the ID (`parseTag`, `utils/tags.js`); any other value is shown as written. Used by Teaser, Page Header, List, Cards, Filter List and Conversation Canvas.

**Rules.** The published namespace is `tcs-corp:` (handover Part 7.1.2; finding F-08: some help texts and examples use `tcs:`). Pick tags with the tag picker; the `aem-tag` fields don't restrict the namespace (handover Part 7.1.1). A selected tag also matches its child tags in List (`hasTag`, handover Part 7.2.2).

**Example.** `tcs-corp:region/europe` → `Europe` from `/en/taxonomy.json`; without a taxonomy entry, an ID-derived label.

**Common mistakes.** Typing tag IDs by hand; not publishing the locale's taxonomy page (labels fall back to IDs; handover F-09 records that only `/en/taxonomy.json` was published when checked); translating tag titles without republishing the taxonomy page. Governance and lifecycle: handover Part 7 — Taxonomy Documentation.

## Placeholders

**Purpose.** All user-facing UI text in code is authorable and translated per locale (AGENTS.md "Accessibility": all UI text comes from placeholders).

**Structure.** `/{locale}/placeholders.json` with columns Key, Text, Description, Category; code uses Key and Text. Keys are compared without case and separators (`Pause Slides`, `pause-slides` and `pauseSlides` match `pauseSlides`). `{name}` variables are filled by `fillPlaceholder`.

**Consumers.** `const t = await getPlaceholders(); t('nextSlide', 'Next slide')` in every block with UI text, the header, footer and `scripts.js` (404 "Go back", key `goBack`). Source: [`utils/placeholders.js`](../../../utils/placeholders.js); key lists per block in the block READMEs ("For Site Administrators").

**Rules.** Code always passes an English fallback. There is no fallback from a locale's sheet to the English sheet: a key missing in `/de-de/placeholders.json` shows the code's English text (handover Part 4.9.3).

**Common mistakes.** Editing the sheet without publishing it; adding a new key in code without adding it to the 13 sheets. Full key list: handover Part 4.5.3.

## References, fragments and inherited metadata

**Purpose.** Pages that aren't content pages but are included in other pages: the header navigation, the footer, alternatives per site area, the footer Canvas page, modals and fragments.

**Structure** (in each locale's `references/`):

| Page | Used by |
| --- | --- |
| `nav` | Header (default Navigation of the locale) |
| `footer` | Footer (default Footer of the locale) |
| `nav-{name}`, `footer-{name}` | Header / Footer when selected in a page's Navigation / Footer (or the `nav` / `footer` sheet column) |
| Footer Canvas page | The Footer block's Conversation Canvas Page |
| `modals/{name}` | Links whose path contains `/modals/` open as a modal (`autolinkModals`); the Modal block |
| Fragments | Fragment block; Tab fragments |

**Inheritance** (`getInheritedMetadata(name)`, [`utils/inherited-metadata.js`](../../../utils/inherited-metadata.js), for `nav`, `footer`, `error-page`):

1. The page's own value (page property or bulk sheet column).
2. Else the nearest parent page's value up to the locale's Home page (`getParentPages`; for the language master up to `/language-master/en`): the parents' published HTML heads are fetched in parallel.
3. Else the default: `references/nav`, `references/footer`, or for 404 `error-pages/404`.

Values may be AEM paths, published paths or paths relative to the locale root (`references/nav-careers`); `resolvePagePath` returns the AEM path in the editor and the published path on the site. Parent values are cached in `sessionStorage` (`tcs-inherited-metadata`) for the browser session.

**Consumers.** [header](../../../blocks/header/README.md) (falls back to the locale's `references/nav` when a configured page can't load; with none published the header stays empty), [footer](../../../blocks/footer/README.md) (adds the Social Links sheet), `loadErrorPage` (404), [fragment](../../../blocks/fragment/README.md), [modal](../../../blocks/modal/README.md), [tabs](../../../blocks/tabs/README.md).

**Rules.** Keep reference pages in `references/` (excluded from the query index and the sitemap); `fragments/` and `modals/` folders anywhere are excluded too. A fragment change shows on every including page once the fragment is published. `loadFragment(path, from)` fetches only paths starting with `/` and stops recursion by the chain of including fragments.

**Example.** Navigation = `references/nav-careers` on `/en/careers` gives every page below it the Careers header unless a page sets its own.

**Common mistakes.** Testing a changed Navigation in the same browser session (cached); leaving `nav` unpublished in a new locale (empty header); placing a fragment outside `references/`, `fragments/` or `modals/` (it gets indexed and listed).

## Data sheets

**Purpose.** Shared structured data per locale, maintained by authors as AEM spreadsheets.

**Structure and consumers** ([`utils/data.js`](../../../utils/data.js); each sheet loaded once per page view, values trimmed, missing sheets give empty lists):

| Sheet (`/{locale}/data/…json`) | Columns | Read by |
| --- | --- | --- |
| `authors` | `author-id`, `name`, `designation`, `bio`, `image`, `linkedin`, `region` | Page Header (`getAuthor`, case-insensitive id), article / blog templates, List feature card and Filter List spotlights (`getAuthors`) |
| `social-links` | `platform`, `url`, `icon`, `sort-order` | Footer (in `sort-order`, rows without one last) |
| `media-contacts` | `id`, `name`, `designation`, `email`, `phone`, `region` | Press release template (`inRegion` by the page's `region`, else all) |
| `locations` | `location-id`, `location-name`, `country`, `region`, `latitude`, `longitude` | `getLocations()` only; no component reads it (handover F-40) |
| `partners` | `partner-id`, `partner-name`, `logo`, `website`, `tier`, `description` | `getPartners()` only; no component reads it (handover F-40) |

**Rules.** The query index excludes `/*/data/**`. Sheet JSON is public: the Authors and Media Contacts sheets publish names, e-mail addresses and phone numbers by design. Column reference and authoring steps: handover Part 9 — Data Sheets Documentation.

**Common mistakes.** An `author-id` on a page that differs from the sheet in case (Filter List and List match exactly; Page Header case-insensitively, handover F-30); unpublished sheets in non-English locales.

## Error pages

**Purpose.** An authorable, locale-specific 404 page.

**Structure.** Edge Delivery serves `404.html` for a missing path; `loadErrorPage` (`scripts/scripts.js`) tries, in order: the inherited **404 Page** (`error-page`) of the missing page's nearest parent; the locale's `/{locale}/error-pages/404`; `/en/error-pages/404`. A page without content (no text, image, picture, video or iframe) is skipped; when none loads the built-in content ("404", "Page Not Found", "Go home" to the locale's Home) stays. Content from another locale gets its `lang` on `<main>`; "Go back" (placeholder `goBack`) is added for same-origin referrers.

**Rules.** 403 and 500 aren't served by Edge Delivery; the authored `error-pages/403` and `500` are for a CDN (not configured: Requires validation). Error pages are excluded from the query index (`/*/error-pages/**`). Details: handover Part 10 — Error Pages.

**Common mistakes.** An empty `error-pages/404` (skipped, the next candidate shows); expecting the 404 Page property of the missing page itself (the lookup starts at its nearest existing parent).

## Redirects

**Purpose.** Per-locale lists of moved pages.

**Structure.** `/{locale}/redirects.json` with Source and Destination columns (either case).

**Rules and status.**

- The platform applies only a root `/redirects.json`; the per-locale sheets are **not applied** automatically. Redirects, including `/` → `/en/`, need another mechanism such as CDN rules (AGENTS.md "Notes"; handover Part 3.8; findings F-36, 16.4). Status: Requires validation (no mechanism configured).
- In code only the List block uses the sheet: `resolveRedirect` points card links to the final target, at most 5 hops, stopping at loops and external destinations ([`utils/redirects.js`](../../../utils/redirects.js)). Filter List, navigation and running text links aren't rewritten.
- Sources must start with `/` (rows without a destination are ignored); paths are compared without query, hash, `.html` and trailing slash.

**Common mistakes.** Expecting a sheet row to redirect visitors; chains of redirects (point sources at final destinations).

## Content governance

Verified rules (enforced by code or configuration):

- Locale resources sit at fixed locations (`references/nav`, `references/footer`, `error-pages/404`, the sheets, `data/*`): code resolves them per locale.
- Navigation, Footer and 404 Page are inherited from parent pages up to Home.
- `hide-in-nav = yes` keeps a page out of List results (not Filter List or the Canvas menu: F-30, F-33).
- Reference, error, data, nav / footer, fragments and modals paths are excluded from the query index.
- Sheets and reference pages take effect only once published.
- No sample content in templates or model defaults (AEM stores definition template values on every new component).

Ownership, review cadences and approval flows: Not recorded in the repository (handover Parts 7.4, 14 and 17 describe proposed processes and open owners).

## Publishing and indexing dependencies

| Change | Must also be published / done | Effect |
| --- | --- | --- |
| New or changed page | Publish the page | Index row and sitemap update; lists show it (see [indexing-and-search.md](./indexing-and-search.md)) |
| Page metadata used by cards | Republish the listed page | List / Filter List cards change; the List page itself needs no republish |
| Sheet (placeholders, metadata, taxonomy, redirects, data) | Publish the sheet | Next page load (each loaded once per page view) |
| Bulk metadata | Sheet listed in `metadata.source` | Metas on matching pages |
| Navigation / footer / fragment | Publish the reference page | Every including page; inherited values in a new browser session |
| Non-image DAM assets (Lottie JSON, videos, captions) | Publish the assets | Served only once published; images travel with the page (AGENTS.md) |
| `helix-query.yaml` | Reindex (Admin API index operation) or republish | Existing rows unchanged until then |
| `LOCALES` | `npm run build:paths`, re-apply `public.json` and `metadata.source` | New paths published |
