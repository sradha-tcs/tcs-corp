## The language master

`/content/tcs-corp/language-masters/en` holds the content that becomes the global site and the regions once final; MSM or separate regional content is not decided yet.

## Site and locale hierarchy

**Purpose.** One Edge Delivery site serves 13 locale sites by path. Each locale owns its pages and its own references, error pages, sheets, data and block library.

**Structure.** The AEM tree `/content/tcs-corp/{country}/{language}` is published at a language-only path. The locales are defined once in `LOCALES` ([`utils/site.js`](https://github.com/sradha-tcs/tcs-corp/blob/main/utils/site.js)); the first entry is the default (`DEFAULT_LOCALE`, `en`).

| --- | --- | --- | --- | --- | --- | --- |
| `us/en` | `/en` | en-US | | `se/sv-se` | `/sv-se` | sv-SE |
| `de/de-de` | `/de-de` | de-DE | | `dk/da-dk` | `/da-dk` | da-DK |

```text
/content/tcs-corp/
├── {country}/{language}/   a locale site; the locale page itself is Home (published as /{locale}/)
│   ├── …                   content pages
│   ├── references/         nav, footer, alternative navs / footers, footer Canvas page, modals, fragments
│   ├── error-pages/        404 (used by 404.html); 403 / 500 for a CDN
│   ├── block-library/      block validation pages; excluded from publishing
│   ├── placeholders        sheet: Key, Text, Description, Category
│   ├── metadata            sheet: bulk metadata
│   ├── taxonomy            taxonomy page (tag, title)
│   ├── redirects           sheet: Source, Destination
│   └── data/               sheets: authors, locations, partners, social-links, media-contacts
├── language-masters/en/     temporary: published at /language-masters/en for review
└── site-global-templates/  template pages authors copy; excluded from publishing
```

**Path mapping (`paths.json`, generated by `npm run build:paths` from `LOCALES` and `REVIEW_ROOTS`).** One generic set per site root: the folder mapping (`/content/tcs-corp/de/de-de/:/de-de/`: child pages and sheets), the Home page mapping (`/content/tcs-corp/de/de-de:/de-de/`) and the taxonomy page (`…/taxonomy:/de-de/taxonomy.json`): 39 mappings for the locales, 3 temporarily for the language master. The sheets (`placeholders`, `metadata`, `redirects`, `data/*`) need no mapping of their own: the folder mapping publishes them at the same path and spreadsheets get `.json` appended; the former 112 per-sheet mappings are kept commented in the generator. `includes`: the 13 locale pages, `/content/dam/tcs-corp/` and `/content/tcs-corp/language-masters/en`; `excludes`: each locale's `block-library` and `block-library/**`, and `site-global-templates` with its children. AEM applies the site configuration's `public.json` → `paths`, not the repository file (AGENTS.md "Notes").

**Locale resolution (code).** `getLocale(pathname)` reads the AEM path when editing (`/content/tcs-corp/de/de-de/…`) and the published path on the site (`/de-de/…`); pages outside a locale (Site Global Templates, drafts) get `en`. Helpers: `localePagePath`, `resolvePagePath`, `localeSheetPath`, `toPublishedPath`, `toAemPath`, `pageLink`, `getParentPages`, `sheetRows`.

**Review roots (KB-D-068).** There are three review roots, each published as a site of its own (KB-D-068): `/language-master/en` (testing page functionality with dummy content, content limitations), `/language-masters/en` (the language master: the migrated tcs.com content, validated with its real sheet data, later the source of the global site and the regions and languages; MSM or not is open until the content is final) and `/design-block-master/en` (the block library and the curated design pages). Pages below each (`REVIEW_ROOTS`) list their own pages from the query index (`indexRoot`), read their own placeholders, redirects, taxonomy and data sheets (`REVIEW_SHEETS`), use their own `references/` and `error-pages/` (`REVIEW_PAGES`) and inherit up to their root page. The temporary review of the language master ends with its rollout (handover Part 3.9, finding F-88).

**Language master URLs (validated 23 October 2026).** The mappings follow Adobe's path mapping rules (https://www.aem.live/developer/authoring-path-mapping): the folder mapping `/content/tcs-corp/language-masters/en/:/language-masters/en/` covers every child page, and the page mapping `/content/tcs-corp/language-masters/en:/language-masters/en/` is the special case that publishes the root page as `/language-masters/en/index`, served at `/language-masters/en/` (the same pattern as `/en/`). No other mapping is needed. The mappings of every language master come from `REVIEW_ROOTS` (`utils/site.js`): `tools/paths/generate-paths.mjs` writes this set for each root, so another language master (e.g. `/language-masters/de`) is added to the code and to `paths.json` with one entry and `npm run build:paths`; `test/site/paths.test.mjs` checks every locale and language master is mapped this way and that `paths.json` is in step.

| AEM page | Preview | Live |
| --- | --- | --- |
| `/content/tcs-corp/language-masters/en` (Home) | `https://main--tcs-corp--sradha-tcs.aem.page/language-master/en/` | `https://main--tcs-corp--sradha-tcs.aem.live/language-master/en/` |
| `/content/tcs-corp/language-masters/en/<path>` (child pages) | `https://main--tcs-corp--sradha-tcs.aem.page/language-master/en/<path>` | `https://main--tcs-corp--sradha-tcs.aem.live/language-master/en/<path>` |

The Home URL ends with `/` (`/language-masters/en` without it is a 404, as `/en`). On 23 October 2026 the child pages, sheets, references and error pages resolved, but the Home page was a 404 and wasn't in the query index: it has to be previewed and published from AEM (Manage Publication on `/content/tcs-corp/language-masters/en`). If it still returns a 404 after publishing, check that the site configuration's `public.json` → `paths` has the page mapping (AEM applies that configuration, not the repository file).

**Rules.**

- Add or change a locale only in `LOCALES`, then run `npm run build:paths` and commit both files; the site administrator re-applies `public.json` and `metadata.source`.
- Nothing is published at `/`: a `/` → `/en/` redirect needs another mechanism (handover F-36).

**Common mistakes.** Editing `paths.json` by hand (it is overwritten by the generator); expecting a repository `paths.json` change to take effect without the site configuration; creating pages directly under `/content/tcs-corp` (not published).

## Localization

- Each of the 13 locales is a separate page tree with its own references, error pages, sheets, data and block library; locales share no content. Link only to the locale's own references and sheets.
- The page language (`<html lang>`) is the page's `language` metadata when valid, else the locale's tag ([decorators/seo-decorator.js](https://github.com/sradha-tcs/tcs-corp/blob/main/decorators/seo-decorator.js)).
- Creating a locale's content, translation projects, MSM live copies, a language switcher and `hreflang` are not implemented in code; the translation process is not recorded (handover Part 4, 4.9.6; open item O-12).
- Month abbreviations in formatted dates are English in every locale; prefer the numeric date formats where a block offers a choice (handover 4.9.7).
- Temporary: pages below `/language-masters/en` read the language master's own references, sheets and index rows until its rollout to `/en` (`REVIEW_*` in [utils/site.js](https://github.com/sradha-tcs/tcs-corp/blob/main/utils/site.js)).
